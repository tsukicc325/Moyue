把下载来的 txt 小说（**包括 100MB 级、GBK 乱码、整本没有换行**这些情况）变成排版精良、翻页跟文件大小无关的电子书。

- 包名：`com.harness.inkreader` ｜ 工程：`C:\Harness\InkReader`
- 规格：`C:\Harness\InkReader-PLAN.md` ｜ 最低 Android 8.0（API 26）｜ 目标 API 35
- 实现：Kotlin + Jetpack Compose（Material 3）｜ 阅读画布自绘 `StaticLayout`

## 功能

**书架**
网格/列表自适应卡片、按书名哈希生成的稳定配色封面、导入进度、只引用原文件（不复制）、
整文件夹递归批量导入、5 种排序（中文按拼音）、分组筛选、书名搜索、重命名、移动到分组、
书籍详情（编码/判定依据/存储方式/位置/时间）、三种语义正确的删除。

**阅读**
两种阅读方式，**默认上下滚动**：内容按「块」排成一条**双向连续轨道** —— 往下滑到离末尾一屏、
往上滑到离开头一屏时都会预取，所以**两个方向跨章都不跳**：往下接下一章的第一页，
往回接上一章的最后一页（从目录跳章之后往回滑也能接着读）。轨道最多留 3 块（内存有界）
且**绝不丢弃正在读的那一块**，位置以可见的那一块为准，顶部条/进度/书签/划线都会自动跟着走。
也可以切回左右翻页（点击分区翻页，左/中/右，可换左手模式）。
另有音量键翻页/滚一屏、翻页动画（无/滑动/覆盖）、
底部抽屉目录（自动滚到当前章）、全书百分比跳转、阅读位置精确恢复、
长按选中整句 → 复制/划线/搜索/笔记、自动翻页与自动滚屏（5–120 秒）、屏幕常亮、页脚开关。

**全文搜索**
逐块扫描整本书，带进度条与取消；结果显示章节名与前后文摘要，点击直接跳到命中处。

**排版与外观**
字号 / 行距 / 字距 / 首行缩进 / 段间距 / 加粗 / 两端对齐 / 左右上下边距、
字体导入（ttf/otf/ttc，带文件头魔数校验）、
**10 套主题**（纸白 / 米黄 / 牛皮纸 / 护眼绿 / 樱粉 / 天青 / 淡紫 / 石墨灰 / 夜间 / 纯黑），
每套主题**整屏生效** —— 正文、顶栏底栏、目录/搜索/笔记抽屉、分隔线边框、滑杆强调色、
状态栏与导航栏图标都会一起变（不是只有正文变）；选择器带色块网格与实时预览卡。
自定义背景图（居中裁剪铺满 + 透明度）、独立亮度（屏幕左侧上下滑动也能调）。

**统计**
阅读时长（墙钟精确）、阅读速度（字/分）、7 天读书天数、7 天柱状图。
字数只统计「同一章内连续向前翻页」读过的内容 —— 跳章与拖进度条不计入，所以速度不会被跳读拉高。

## 100MB 是怎么读的

反面教材：把整个文件读成 `String`。100MB GBK ≈ 5000 万汉字，转 UTF-16 就是 100MB+ 堆内存，必 OOM。

这套实现的四个关键点：

1. **按字节流分块扫描**，全程只保留一个 1MB 缓冲，**从不把文件读成字符串**。
2. **字节级找换行**：`0x0A`/`0x0D` 不可能出现在 UTF-8 续字节（0x80–0xBF）或 GBK 尾字节
   （0x40–0xFE 且第 2/4 字节是 0x30–0x39）里，所以按字节找换行是**精确**的，章节偏移零成本得到，
   不需要回写重编码去推算。UTF-16/32 不满足这个前提，导入时会被自动转码成 UTF-8。
3. **标题行必然很短**：先用字节长度（≤120）过滤，只对极少数候选行解码做正则。
   100MB 正文里数十万个长段落**从未被解码过**。
4. **章节内部再分块**（32KB）：因为「100MB 只有 5 章」意味着单章 20MB。
   块边界吸附到行首且**确定性可复现**，所以保存的阅读位置永远有效。

### 实测（详见 [docs/BENCH.md](docs/BENCH.md)）

| 场景 | 索引耗时 | 章节数 | 峰值堆增量 |
|---|---|---|---|
| 100MB GBK 有章节 | **266 ms** | 24 040 | 27.0 MB |
| 100MB UTF-8 有章节 | **254 ms** | 16 062 | 18.9 MB |
| 100MB GBK **整本无换行** | **128 ms** | 100 | **2.5 MB** |

第三行是关键证据：最恶劣的输入下峰值堆增量只有 2.5MB，说明超长行**一个字节都没被读进字符串**。

长程稳定性：150 次「分块读取 + 排版」+ 3 次全本搜索 + 2 次重建索引后峰值堆增量 42.3MB；
连续翻 400 页位置单调不回退。

## 代码结构

```
app/src/main/java/com/harness/inkreader/
  InkApp.kt                  仓库/设置/字体仓库的装配，外部导入入口
  MainActivity.kt            音量键拦截、import_path intent
  engine/                    与界面无关的阅读引擎
    EncodingDetector.kt      BOM → 严格 UTF-8 → chardet → GB18030，并对候选实际打分
    ChapterRule.kt           章节正则 + 中文数字解析 + 形状过滤
    ChapterIndexer.kt        流式索引：精确字节偏移、虚拟分章兜底、序号序列过滤
    ByteSource.kt            统一 file:// 与 content:// 的随机读取
    ChapterBlocks.kt         确定性分块 + 解码（段首替换字符/BOM 清理）
    TextPaginator.kt         StaticLayout 排版 + 切页数学 + 段间距 span
    FullTextSearcher.kt      整本搜索（复用分块，命中即阅读器坐标）
    Charsets.kt              判断某个编码能否按字节找换行
  data/
    Entities.kt Daos.kt InkDatabase.kt      Room 持久化
    BookRepository.kt        导入 → 探测 → 索引 → 落库 → 进度/书签/笔记/会话
    DocumentScanner.kt       文件夹递归收集 txt
    ReadingStats.kt          统计模型与按天聚合
    settings/                设置模型 + DataStore 落盘 + 字体仓库
  ui/
    InkNav.kt Fonts.kt VolumeKeyBus.kt
    bookshelf/               书架、排序筛选引擎、书籍管理对话框
    reader/                  阅读页、状态机、翻页动画几何
    settings/ stats/ theme/  设置面板、统计、配色
```

**分层原则**：`engine/` 不依赖界面也不依赖 Android 的 Context（`ChapterIndexer`、`ChapterBlocks`、
`FullTextSearcher`、`EncodingDetector` 都能在纯 JVM 上跑）；`data/` 只做持久化与编排；
坐标系统一用 **(章节, 块号, 块内字符偏移)**，进度、书签、笔记、搜索结果都用这一套。

## 构建

需要 **JDK 17+**（本机用 21）与 Android SDK（`compileSdk 35`）。仓库自带 Gradle Wrapper：

```bash
export ANDROID_HOME=/path/to/android-sdk      # Windows: $env:ANDROID_HOME='...'

./gradlew assembleDebug        # 调试包，可直接侧载
./gradlew assembleRelease      # 发布包（用 debug 签名，同样可安装；已过 lintVitalRelease）
./gradlew testDebugUnitTest    # 189 个单元测试（含 Robolectric）
./gradlew lint
```

产物：

- `app/build/outputs/apk/debug/app-debug.apk`（约 10.8 MB）
- `app/build/outputs/apk/release/app-release.apk`（约 7.4 MB）

> **关于这个仓库的构建环境**：开发机在 Maven Central 上实测只有 25KB/s，所以 `settings.gradle`
> 把阿里云镜像排在前面（Compose/Room 仍走 google maven）。Robolectric 用离线模式指向本地
> 预下载的 jar，避免它自己拉 190MB；如果你在别的机器上跑测试，把
> `app/build.gradle` 里 `robolectric.offline` / `robolectric.dependency.dir` 两行去掉即可
> （Robolectric 会自己下载）。

## 真机验证（一条命令）

手机用数据线连上、开启「开发者选项 → USB 调试」并允许授权，然后：

```powershell
pwsh -NoProfile -File C:\Harness\InkReader\tools\device-check.ps1
# 加 -IncludeHuge 会额外推一本 100MB 小说，验证索引速度
# 加 -SkipInstall  跳过安装，只跑交互验证
```

它会做完这些事，并把截图、日志、数据库报告写进 `device-evidence\`：

1. 确认设备已授权 → 2. 安装 APK → 3. 生成并推送测试小说（GBK/UTF-8/UTF-16/单行/可选 100MB）
→ 4. 用 `inkreader.import_path` intent 直接灌入（**不经过系统文件选择器**）→ 5. 等待书出现在书架
→ 6. 打开、翻页、返回、呼出菜单、目录 → 7. 加书签 → 8. 用 ASCII 标记词搜索并查看结果
→ 9. 长按选中并划线 → 10. 打开自动翻页 → 11. 拉取 SQLite 数据库并用
`tools/dump_db.py` **校验一致性**（章节是否首尾相接、进度是否落在存在的章节里、会话时间是否合法）
→ 12. 抓 logcat 检查崩溃/ANR → 13. 汇总关键检查结果（有失败则退出码 1）。

> 脚本刻意写成**全 ASCII**：Windows PowerShell 5.1 会把无 BOM 的 UTF-8 文件按 GBK 解码，
> 中文注释可能吃掉引号导致**语法**错误（不只是显示乱码）。所以请用 `pwsh`（PowerShell 7）运行。

配套工具：

```powershell

# 校验任意一个拉回来的数据库
```

## 开发过程中被抓出来的真实缺陷

这些问题都不是靠「看代码」发现的，而是测试逼出来的（详见 [docs/STATUS.md](docs/STATUS.md)）：

1. `PageSplitter` 把页内相对高度当绝对偏移 → **翻到第 3 页起显示错误文字区间**
2. Big5 字节能被 GB18030 解成合法汉字 → 繁体小说**整本乱码**
3. 无 BOM 的 UTF-16 在 ASCII 区间是合法 UTF-8 → 误判后正文全是 NUL
4. 「至少 3 个章节才采信真实章节」的阈值 → **两章的书真实章节名全丢**
5. `applySettings` 在锁外发布新 spec，在途的旧重排随后写回旧排版 → 拖字号时**先按旧字号渲染一帧**
6. `repaginateLocked` 在异步分页期间算好页码、结束后才写回 → **悄悄撤销用户翻的那一页**
7. 全文搜索器用默认分块粒度，与阅读器可配置的粒度不一致 → **点搜索结果跳到错误位置**
   （生产中两者恰好都是 32KB，属于「碰巧能跑」的耦合）
8. 笔记没有 trim

真机验证（手机接上后）又抓出四个，都是自动化测试覆盖不到的：

9. 章节序号过滤要求「递增且跨度 ≤50」→ **用户几千章的书只剩一百多章**。
   该书 2445 章里有 2255 章的标题是 `第九卷 灵界百族 第一千四百二十二章 须弥洞天图`
   这种**卷号章号同行**的格式，正则抓到的是**卷号**（11），过滤器一看 11 小于上一个章号，
   就把后面的章节整片丢弃 —— 修复前后 190 → 2445 章
10. 滚动模式的手势层盖在列表上面 → Compose 只把事件给最上面的兄弟节点，**完全滑不动**
11. 滚动模式的「自动接下一章」挂在列表项里 → 列表会提前组合视口外的项，**一打开就自己往前跑**
12. 滚动模式按页切片绘制（平移 `-topPx` 后裁剪）→ 文字被画到节点边界外，真机裁掉，
    **只有每章开头有字、往下全是空白**
13. 滚动模式的滚动容器占满全屏 → 正文从**页脚底下穿过去**（页脚文字与正文叠在一起）
14. 轨道窗口收缩时无脑丢头部 → **丢掉用户正在读的那一块**，列表为保持可见项只能跳走
    （真机表现：读着读着突然跳回本章第 10 页）。修法：正在读的块永不丢
15. 滚动模式「轨道重置后归位」的 effect 跑在列表还没有 items 时，`scrollToItem` 被夹到 0，
    位置观察者又把 0 回写状态 → **打开书时恢复出来的阅读位置丢失**

> 还有两个「差点误修」的，都是**验证手段本身出错**，不是 app 的问题：
> ① 升级后截图里字看着变大，量了设置才发现字号就是正常的 18 —— 是我早先测试误拖到 12，
>    后面的验证截图全是 12sp 的，我拿它当了基准。
> ② 一度判断「目录跳章是坏的」，其实是**我 PowerShell 里解析 uiautomator 坐标写错了**
>    （`[0,2090][1260,2226]` 用 `-split '[,]'` 拆成三段），算出的 y 是 10450630，
>    点击从来没落在章节行上。改用正则抓两组数字后，跳章一次就对。
> **凡是靠 UI 读数下结论的地方，都要再用一个独立数据源（这里是 SQLite 里的真实进度）对一遍。**

> 还有一个「差点误修」的：升级后截图里字看着变大，我一度以为是渲染 bug。
> 量了设置才发现字号就是正常的 18 —— 是我早先测试时误拖到 12，后面的验证截图全是 12sp 的。
> **先量数值再改代码**，省掉一次凭感觉的瞎改。

> 最重要的两条教训：
> **①「先发布状态、再异步补上配套数据」在多线程下必然出错** —— 状态里的 spec 与 paged 必须成套写入。
> **② 两个组件共享一套坐标系时，粒度参数必须显式传递**，「恰好都是默认值所以能跑」是最危险的耦合。
